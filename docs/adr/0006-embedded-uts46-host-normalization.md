# 0006 - Embedded UTS #46 host normalization (no ICU)

Status: accepted (LF-16)

## Context
A scanned host must become one comparable name before any rule runs: `ｂｉｔ.ｌｙ。`, `%70aypal.com`, `１２７.０.０.１`, `xn--pypal-4ve.com` and `раураl.com` must be seen as a browser sees them, and that single form is the one analysed and displayed (T-CNT-4, T-CNT-7). That is UTS #46 (IDNA compatibility processing, non-transitional) plus Punycode (RFC 3492). The platform does not provide it: `java.net.IDN` is IDNA2003 (frozen at Unicode 3.2), `android.icu.text.IDNA` needs API 24 and minSdk is 23 (D8). The decoder also needs a result that does not change with the Unicode version of the phone's runtime.

## Options compared
| Option | Cost in the APK (after R8) | Maintenance | Licence | Verdict |
|---|---|---|---|---|
| ICU4J (`com.ibm.icu:icu4j`) | about 13 MB for the full jar; `icu4j-core`-style trimming with R8 still keeps the IDNA, normalizer and property data, several MB | upstream releases follow Unicode; Renovate would bump it | Unicode License | too heavy for a feature that needs mapping tables only |
| `android.icu` | 0 | depends on the phone | platform | needs API 24; results depend on the device's ICU version |
| `java.net.IDN` | 0 | none | JDK/platform | IDNA2003: wrong mapping for `ß`, `ς`, fullwidth edge cases, Unicode 3.2 only; fails the conformance suite |
| Other small libraries (ada-url JNI, idna-java ports) | JNI or unmaintained forks | single maintainer | mixed | native code or unmaintained: no |
| **Embedded minimal implementation generated from the Unicode files** | about 365 KB of text resources before compression (about 130 KB in the APK), 600 lines of Kotlin | regenerate with `scripts/gen-host-data.py` when Unicode or the PSL changes | Unicode License v3 (data), MPL-2.0 (PSL) | chosen |

The size of the chosen option is measured on the release APK by the full gate (`ci.yml`, see the LF-16 pull request); ICU4J was not built because its published size is already beyond the 2 MB bar.

## Decision
- No new dependency. The `domain.host` package implements UTS #46 non-transitional processing (`Uts46`), Punycode (`Punycode`), the Public Suffix List (`PublicSuffixList`), scripts and UTS #39 confusables (`ScriptData`, `Confusables`) from data files generated by `scripts/gen-host-data.py` out of the official sources: IdnaMappingTable.txt, DerivedBidiClass.txt, DerivedJoiningType.txt, DerivedCombiningClass.txt, DerivedGeneralCategory.txt, Scripts.txt, confusables.txt and public_suffix_list.dat. The files live in `app/src/main/resources/lookfirst/host/` (Java resources: they load the same way in unit tests on the JVM and in the APK, and `domain/` stays free of Android imports). Each file carries its source version and licence in its header.
- Properties that UTS #46 needs (Bidi_Class, Joining_Type, virama, marks) are embedded too, not read from `java.lang.Character`, so the verdict does not depend on the Unicode version of the device. Only NFC / NFD come from `java.text.Normalizer` (available since API 9); a code point added after the runtime's Unicode version simply does not compose.
- Conformance: `Uts46ConformanceTest` runs the whole official `IdnaTestV2.txt` (6,396 cases, every flag on: STD3, CheckHyphens, CheckJoiners, CheckBidi, VerifyDnsLength) and `PublicSuffixListTest` runs the official PSL test vectors; `PunycodeTest` checks the RFC 3492 vectors.
- Production parameters follow the WHATWG URL standard (no STD3 rules, no hyphen check, non-transitional) plus DNS length limits and an explicit forbidden-host-code-point check on the mapped result (a fullwidth `＠` maps to `@` and must not survive).
- A missing or unreadable data file never crashes and never passes silently: the normalizer returns `HostError.DATA_UNAVAILABLE` and the analysis reports ANALYSIS_INCOMPLETE.

## Consequences
- The data is a snapshot (Unicode 18.0.0, PSL of 2026-10-16). Refreshing it is a script run and a PR; the signed reputation bundle (D13) will later carry a fresher PSL, and `PublicSuffixList.parse` already accepts that format.
- About 7,500 mapping ranges, 3,300 confusables and 10,000 PSL rules are parsed on first use (a few tens of milliseconds, once); the analysis must run off the main thread (already required by T-CNT-9).
- The confusables table keeps only sources that IDNA allows, so it stays small; it is a skeleton for comparing with brand names, never a proof on its own (T-CNT-6).
- The brand list is a local, hand-maintained list of about 270 entries (`BrandList`); it is refreshed with the reputation bundle later.
- Displaying the normalized form (Unicode and punycode) to the user is done by the verdict screen (LF-18); the Result screen (LF-11) does not show it yet and only warns about non-Latin characters.

## Data provenance (LF-20)
- `scripts/gen-host-data.py` holds `SOURCES`: the exact versioned URL (unicode.org `Public/18.0.0/...`; publicsuffix/list at commit `2dbfce14c57bcea83fef2be3bdcb560667d7ef93`, 2026-10-16) and the expected SHA-256 of every source, test vectors included. Each generated file names its sources (URL, version, SHA-256) in its header, and `SHA256SUMS` lists the SHA-256 of the generated files (`HostDataIntegrityTest` checks them: internal consistency only, not provenance).
- `scripts/gen-host-data.py --verify` downloads the sources, checks their SHA-256, regenerates in a temporary directory and compares byte for byte with the committed files (exit code 1 on any difference). Provenance is `--verify`, not the unit test. Workflow `data-provenance.yml` runs it weekly, by hand and on every pull request touching the data, the script or the workflow. If it fails after a runner image change, the Python version (NFC / lower() in the punycode step) is the first suspect.
- Update Unicode or the PSL: change the URLs, versions and SHA-256 in `SOURCES`; `scripts/gen-host-data.py --download DIR` (checks the hashes); `scripts/gen-host-data.py DIR app/src/main/resources/lookfirst/host`; copy `IdnaTestV2.txt` and `test_psl.txt` to `app/src/test/resources/lookfirst/host/`; read the diff of the data files (a version bump changes data, not only headers); run `--verify` and the tests; one PR.
